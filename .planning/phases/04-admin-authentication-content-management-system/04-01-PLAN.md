# Plan 04-01: Admin Authentication, Session Middleware & Protected Admin Shell

<threat_model>
## Security Threat Model (ASVS Level 1)

| Threat | ASVS Requirement | Mitigation Strategy |
|---|---|---|
| Unauthenticated Admin Access / Broken Object Level Auth | V4.1.1 (Access Control) | Next.js middleware and Server Components strictly verify active Supabase Auth session AND query `profiles.role === 'admin'`. Unauthenticated or non-admin users are rejected and redirected. |
| Session Fixation / Hijacking | V3.3.1 (Session Management) | Cookies are set with `HttpOnly`, `SameSite=Lax`, and `Secure` attributes via `@supabase/ssr`. Logout explicitly clears session cookies on client and server. |
| Credential Brute Forcing | V2.2.1 (Authenticator Security) | Login inputs are sanitized and rate-limited. Passwords are never logged or stored in client-side storage. |
</threat_model>

<user_story>
**As an** administrator or editor of Diwang Panlipunan,  
**I want** to securely log into the CMS using my email and password and access protected administration screens,  
**so that** unauthorized visitors cannot alter educational content or societal analyses.
</user_story>

<task id="04-01-01" type="auto">
  <name>Build Supabase Session Middleware & Route Protection [AUTH-02, AUTH-03, D-02]</name>
  <read_first>
    - .planning/phases/04-admin-authentication-content-management-system/04-CONTEXT.md
    - src/lib/supabase/server.ts
    - src/lib/supabase/client.ts
    - src/types/database.ts
  </read_first>
  <action>
    1. Create `src/lib/supabase/middleware.ts`:
       - Implements `updateSession(request: NextRequest)` using `@supabase/ssr` `createServerClient`.
       - Manages request and response cookies.
       - Fetches user session via `supabase.auth.getUser()`.
       - If route begins with `/admin` and is not `/admin/login`:
         - If no user, redirects to `/admin/login?next=${pathname}`.
         - If user exists, queries `profiles` table to verify `role === 'admin'`.
         - If role is not admin, redirects to `/admin/login?error=unauthorized`.
    2. Create `src/middleware.ts`:
       - Invokes `updateSession`.
       - Matches all routes except static assets, favicon, and `_next`.
  </action>
  <acceptance_criteria>
    - `src/lib/supabase/middleware.ts` and `src/middleware.ts` created
    - All routes under `/admin/*` (except `/admin/login`) require authenticated admin session
    - Unauthenticated requests redirect to `/admin/login`
  </acceptance_criteria>
  <verify>
    Verify middleware compiles and catches unauthenticated `/admin` requests via `npm run build`.
  </verify>
  <done>
    Middleware session protection is active.
  </done>
</task>
