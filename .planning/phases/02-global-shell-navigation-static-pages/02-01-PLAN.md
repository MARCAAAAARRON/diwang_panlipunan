# Plan 02-01: Global Shell, Persistent Header, Theme Provider & Zero-FOUC Script

<threat_model>
## Security Threat Model (ASVS Level 1)

| Threat | ASVS Requirement | Mitigation Strategy |
|---|---|---|
| Cross-Site Scripting (XSS) via Theme Injection | V5.1.3 (Input Sanitation) | The inline head script strictly sets `data-theme` to either `"dark"` or `"light"` via strict equality whitelist checks against localStorage values. Arbitrary string values from localStorage are never reflected directly into HTML attributes or evaluated. |
| Insecure External Link Manipulation | V14.2.1 (Component Isolation) | All external links (e.g. references, email links, social links) use `rel="noopener noreferrer"` and appropriate target attributes to prevent tab-nabbing. |
| DOM Traversal & Header Injection | V5.3.1 (Output Encoding) | Search input in the persistent header is purely a presentational search input placeholder in this phase and does not evaluate or inject unescaped HTML. |
</threat_model>

<user_story>
**As a** reader of Diwang Panlipunan,  
**I want** a persistent broadsheet header with a drawer hamburger toggle, search placeholder, theme switcher, and high-contrast light/dark mode without screen flicker,  
**so that** I can seamlessly navigate the publication and comfortably read in any lighting condition.
</user_story>

  <name>Implement zero-FOUC theme script and ThemeProvider [NAV-03, D-08, D-09]</name>
  <read_first>
    - .planning/phases/02-global-shell-navigation-static-pages/02-CONTEXT.md
    - docs/DESIGN.md §2 (Color System)
    - src/app/globals.css
    - src/app/layout.tsx
  </read_first>
  <action>
    1. Create `src/components/theme/theme-provider.tsx`:
       - Client component (`"use client"`) providing `ThemeContext` with current theme (`"light"` | `"dark"`), `toggleTheme()`, and `setTheme()`.
       - Reads theme from `document.documentElement.getAttribute('data-theme')` on mount.
       - Dispatches changes to `localStorage.setItem('theme', theme)` and toggles `data-theme` attribute and `dark` class on `document.documentElement`.
       - Listens to system color scheme changes (`matchMedia('(prefers-color-scheme: dark)')`) when no explicit preference is stored in `localStorage`.
    2. Create `src/components/theme/theme-toggle.tsx`:
       - Header toggle button styled according to `DESIGN.md`: surface background, 1px border, 6px radius (`rounded-md`), minimum 44px touch target.
       - Renders Lucide `Sun` (when dark) or `Moon` (when light) icon.
       - Text label in English: `"Dark mode"` when in light mode, `"Light mode"` when in dark mode (adhering to the bilingual rule in `DESIGN.md`).
    3. Update `src/app/layout.tsx`:
       - Inject an inline blocking `<script>` inside `<head>` that executes before browser paint:
         ```javascript
         (function() {
           try {
             var stored = localStorage.getItem('theme');
             var isDark = stored ? stored === 'dark' : window.matchMedia('(prefers-color-scheme: dark)').matches;
             var theme = isDark ? 'dark' : 'light';
             document.documentElement.setAttribute('data-theme', theme);
             if (isDark) {
               document.documentElement.classList.add('dark');
             } else {
               document.documentElement.classList.remove('dark');
             }
           } catch (e) {}
         })();
         ```
       - Wrap layout children in `<ThemeProvider>`.
  </action>
  <acceptance_criteria>
    - Inline script exists in `<head>` in `src/app/layout.tsx` executing before body rendering
    - Toggling the theme switches `data-theme="dark"` / `data-theme="light"` on `document.documentElement`
    - `localStorage.getItem('theme')` is persisted across page reloads
    - Zero FOUC occurs on page reload when dark mode is enabled
  </acceptance_criteria>
  <verify>
    Run `npm run build` to verify no SSR/hydration mismatches or syntax errors.
    Test `data-theme` attribute presence and localStorage persistence.
  </verify>
  <done>
    Theme provider, zero-FOUC script, and theme toggle button are functioning cleanly.
  </done>
