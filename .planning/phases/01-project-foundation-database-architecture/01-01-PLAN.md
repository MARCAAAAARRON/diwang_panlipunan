# Plan 01-01: Project Scaffold, Editorial Tokens, Typography & Supabase Client

<threat_model>
## Security Threat Model (ASVS Level 1)

| Threat | ASVS Requirement | Mitigation Strategy |
|---|---|---|
| Exposure of Service Role Key | V1.4.1 (Access Control Architecture) | Only `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` are exposed to browser bundles. `SUPABASE_SERVICE_ROLE_KEY` is strictly reserved for server-side administrative tasks and never prefixed with `NEXT_PUBLIC_`. |
| Insecure Client Session Handling | V3.2.1 (Session Management) | Use `@supabase/ssr` official cookie handling via `createBrowserClient` and `createServerClient` ensuring sessions are synchronized across Server Components and Client Components without vulnerable localStorage token storage. |
| Insecure CSS / Font Loading | V14.4.1 (Content Security) | Use Next.js native `next/font/google` for self-hosted zero-roundtrip Google Fonts (`Source Serif 4` and `Public Sans`) avoiding runtime third-party font tracking and layout shifts. |
</threat_model>

<user_story>
**As a** developer and learner,  
**I want** a structured Next.js App Router workspace with high-contrast editorial design tokens, fonts, and an SSR-ready Supabase client,  
**so that** all future pages and components render with journalistic aesthetic rigor and type-safe database connectivity.
</user_story>
