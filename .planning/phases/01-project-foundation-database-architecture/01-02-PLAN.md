# Plan 01-02: Supabase Schema, RLS Policies, Seed Data & Walking Skeleton Verification

<threat_model>
## Security Threat Model (ASVS Level 1)

| Threat | ASVS Requirement | Mitigation Strategy |
|---|---|---|
| RLS Bypass / Unauthorized Data Mutation | V1.4.1 (Access Control Architecture) | Enable Row Level Security (RLS) on all 6 tables (`profiles`, `topics`, `subtopics`, `sources`, `feedback`, `suggestions`). Anonymous visitors can only read published content and submit structured feedback/suggestions. All mutations require `is_admin()`. |
| Privilege Escalation on User Profiles | V4.1.1 (Role-Based Access Control) | Protect `public.profiles` with strict RLS: users cannot alter their own `role` column. Role elevation to `'admin'` is restricted to server-side scripts or verified admin profiles. |
| SQL Injection in tsvector Search | V5.3.1 (Output Encoding & SQL Injection) | Use PostgreSQL parameter binding in Supabase queries and configure `to_tsvector('simple', ...)` to prevent command injection in search strings. |
</threat_model>

  <action>
    Create `supabase/migrations/00002_rls_and_auth.sql`:
    1. Function `handle_new_user()` returning trigger that automatically inserts `id`, `email`, and `full_name` from `auth.users` into `public.profiles` (D-08). Attach trigger to `auth.users`.
    2. Security Definer function `is_admin()`:
       ```sql
       create or replace function public.is_admin()
       returns boolean language sql security definer set search_path = public stable as $$
         select exists (
           select 1 from public.profiles
           where id = auth.uid() and role = 'admin'
         );
       $$;
       ```
    3. Enable Row Level Security on all 6 tables:
       - `profiles`: SELECT allowed for authenticated user's own profile OR `is_admin()`; UPDATE allowed for user on non-role columns OR `is_admin()`.
       - `topics`: SELECT allowed for all if `is_published = true` OR `is_admin()`; INSERT/UPDATE/DELETE restricted to `is_admin()`.
       - `subtopics`: SELECT allowed for all if `is_published = true` and parent topic `is_published = true` OR `is_admin()`; INSERT/UPDATE/DELETE restricted to `is_admin()`.
       - `sources`: SELECT allowed for all on published subtopics OR `is_admin()`; INSERT/UPDATE/DELETE restricted to `is_admin()`.
       - `feedback`: INSERT allowed for all (public feedback); SELECT restricted to `is_admin()`.
       - `suggestions`: INSERT allowed for all (public suggestions); SELECT/UPDATE restricted to `is_admin()`.
  </action>
