# Plan 05-02: In-Article Reader Feedback & Public Topic Suggestion Box

<threat_model>
## Security Threat Model (ASVS Level 1)

| Threat | ASVS Requirement | Mitigation Strategy |
|---|---|---|
| Automated Spam & Bot Flooding on Public Forms | V11.1.4 (Business Logic Limits) | Hidden honeypot field (`website_url_hp`) detects automated bot submissions. IP/client cookies enforce rate limiting (max 5 suggestions per hour). |
| Stored XSS in Reader Comments & Suggestions | V5.1.3 (Input Sanitation) | Inputs are strictly validated with Zod schemas. Reader comments and suggestions are text-sanitized and rendered safely as encoded strings. |
| Duplicate Voting / Feedback Manipulation | V11.1.2 (Abuse Prevention) | Local browser storage stores article vote locks (`diwang_feedback_[slug]`) and server checks IP/timestamp rate windows. |
</threat_model>

<user_story>
**As a** reader or citizen learner,  
**I want** to provide feedback on articles and suggest contemporary societal topics that matter to our communities,  
**so that** Diwang Panlipunan continues to reflect urgent civic realities and public educational needs.
</user_story>

    1. Create `src/lib/feedback-actions.ts`:
       - Server action `submitFeedback(subtopicId: string, isHelpful: boolean, comment?: string)`:

       - Check `localStorage.getItem(\`diwang_feedback_\${subtopicSlug}\`)` on mount to display previous vote state if already submitted.
       - On clicking "Oo" or "Hindi":
         - Calls `submitFeedback(subtopicId, isHelpful)`.
         - Saves vote flag in `localStorage`.
         - Expands an optional inline comment field: `"May nais ka bang idagdag o imungkahi upang mapabuti ang araling ito?"`.
         - Submits comment via `submitFeedback` on pressing `"Ipadala ang Puna"`.
  </action>

    - Locks vote locally to prevent repeated voting

  </acceptance_criteria>

<task id="05-02-02" type="auto">
  <name>Implement Public Suggestion Box at `/magmungkahi` [SUGG-01, SUGG-02, D-04]</name>
  <read_first>
    - .planning/phases/05-full-text-search-feedback-suggestion-box/05-CONTEXT.md
    - src/types/database.ts
    - src/lib/content-service.ts
  </read_first>
  <action>
    1. Create `src/lib/suggestion-actions.ts`:
       - Define Zod schema `suggestionSchema`:
         - `title`: string, min 5 chars, max 150 chars
         - `topic_id`: valid UUID string matching a core topic
         - `reason`: string, min 20 chars, max 1000 chars
         - `suggested_sources`: optional string, max 500 chars
         - `submitter_name`: optional string, max 100 chars
         - `submitter_email`: optional email string
         - `website_url_hp`: honeypot field (must be empty or submission is rejected)
       - Server action `submitTopicSuggestion(formData: FormData)`:
         - Validates fields via Zod. Rejects bot if honeypot is filled.
         - Inserts into `suggestions` table with status `'pending'`.
         - Revalidates `/admin/suggestions`.
    2. Create `src/app/magmungkahi/page.tsx`:
       - Broadsheet editorial layout with header: `"Magmungkahi ng Paksa o Suliraning Panlipunan"`.
       - Civic rationale notice explaining how public submissions guide the editorial board.
       - Form fields with real-time validation and Filipino error messages:
         - Suggested Topic Title
         - Parent Theme selector (dropdown of 7 topics)
         - Rationale / Educational Context textarea
         - Recommended Primary Sources / Articles
         - Submitter Name & Email (optional)
         - Hidden honeypot field
       - Success confirmation banner upon submission with return link to `/home`.
    3. Update `next.config.mjs` to add rewrite for `/suggest` -> `/magmungkahi`.
  </action>
  <acceptance_criteria>
    - Public submission form validates inputs via Zod schema
    - Honeypot and rate limiting protect against spam
    - Submissions persist to `suggestions` table with status `'pending'`
    - `/suggest` rewrites to `/magmungkahi`
  </acceptance_criteria>
  <verify>
    Verify `/magmungkahi` builds cleanly via `npm run build`.
  </verify>
