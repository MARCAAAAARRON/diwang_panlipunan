# Plan 05-01: Full-Text Search Engine, Live Search Modal & Results Page

<threat_model>
## Security Threat Model (ASVS Level 1)

| Threat | ASVS Requirement | Mitigation Strategy |
|---|---|---|
| SQL / Query Parameter Injection via Search Terms | V5.1.3 (Input Sanitation) | Search inputs are stripped of malicious control characters and passed through parameterized Supabase queries using PostgreSQL `websearch_to_tsquery` or `plainto_tsquery('simple', ...)`. Direct string interpolation in SQL is strictly prohibited. |
| Denial of Service (DoS) via Complex Search RegExes | V11.1.1 (Business Logic) | Search queries are capped at 100 characters and client input is debounced (300ms) to limit search query volume. |
| XSS via Highlighted Search Snippets | V5.3.1 (Output Encoding) | Highlighted keyword snippets are securely generated using React nodes rather than raw `dangerouslySetInnerHTML`. |
</threat_model>

<user_story>
**As a** student or researcher,  
**I want** to search contemporary Philippine societal issues by keyword from anywhere on the platform using a search modal or dedicated results page,  
**so that** I can rapidly locate relevant subtopics, statistics, and editorial analyses across the 7 themes.
</user_story>

<task id="05-01-01" type="auto">
  <name>Build Bilingual Full-Text Search Service with Resilient Fallback [SRCH-02, D-02]</name>
  <read_first>
    - .planning/phases/05-full-text-search-feedback-suggestion-box/05-CONTEXT.md
    - src/lib/content-service.ts
    - src/lib/supabase/server.ts
    - src/types/database.ts
  </read_first>
  <action>
    Create `src/lib/search-service.ts`:
    1. Define `SearchResultItem` interface:
       - `id: string`
       - `title: string`
       - `slug: string`
       - `topicSlug: string`
       - `topicNameFil: string`
       - `topicColorToken: string`
       - `summary: string`
       - `matchedSnippet: string`
       - `readTimeMinutes: number`
    2. Implement `searchContent(query: string): Promise<SearchResultItem[]>`:
       - Sanitizes query, enforces 100-character max length. Returns empty array if trimmed query is shorter than 2 characters.
       - Attempts PostgreSQL `search_vector` query via Supabase:
         `supabase.from('subtopics').select('*, topic:topics(*)').textSearch('search_vector', query, { config: 'simple', type: 'websearch' }).eq('is_published', true)`
       - Resilient Fallback: If database is unreachable or yields no results, executes weighted in-memory search across canonical `SEED_TOPICS` from `content-service.ts` matching title (weight 3x), summary (weight 2x), and content markdown (weight 1x).
    3. Excerpts & Snippets Helper:
       - Extracts relevant ~120 character contextual excerpt surrounding the first matched query word.
  </action>
  <acceptance_criteria>
    - `searchContent` handles Filipino and English terms
    - Gracefully falls back to seed dataset in offline/pre-DB mode
    - Returns structured results with topic metadata and matched snippet
  </acceptance_criteria>
  <verify>
    Verify `searchContent` passes TypeScript compilation and type checks.
  </verify>
  <done>
    Search service with hybrid fallback is operational.
  </done>
</task>
